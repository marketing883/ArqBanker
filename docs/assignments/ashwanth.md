You are responsible for case workflow, backend APIs, policy recommendations, audit logging, and evidence package generation.

Build this part of the flow:

```text
risk-scored case -> backend workflow -> human action -> audit trail -> evidence package
```

```text

Why was it allowed?
Can we prove it later?
```

## 7. Case Workflow

Support these case statuses:

```text
new
assigned
investigating
pending_filing
resolved
escalated
auto_resolved
closed
```

For the POC, implement simple rules:

```text
When an analyst opens or accepts a case -> investigating
When block_transaction action happens -> pending_filing
When evidence package is generated -> pending_filing
When close_case action happens -> closed
When escalate action happens -> escalated
```

Do not make regulatory decisions automatically.

## 8. Human Actions

Support these action types first:

```text
accept_case
block_transaction
restrict_account
send_secure_message
generate_sar_draft
escalate
close_case
```

Every action must:

- Have an actor.
- Have a role.
- Have a timestamp.
- Have a summary.
- Be added to the case.
- Create an audit event.

## 9. Policy Recommendations

Create a simple policy module:

```text
backend/app/policy.py
```

For the POC, support:

```text
OFAC recommendation
BSA/SAR recommendation
```

Important rule:

```text
The policy engine recommends. It does not execute.
```

Every policy recommendation should include:

- Policy ID.
- Regulation.
- Title.
- Recommendation.
- Severity.
- Due date if relevant.
- `requires_human_confirmation = true`.

## 10. Audit Hash Chain

The audit system is very important.

Every audit event must store:

- Event ID.
- Sequence number.
- Created time.
- Actor.
- Role.
- Event type.
- Entity type.
- Entity ID.
- Summary.
- Payload.
- Previous hash.
- Event hash.

The function:

```python
verify_hash_chain(events)
```

must return:

```text
true
```

when the event chain has not been changed.

Add tests for this.
